### Overview
Investigated and fixed multiple issues with the forge orchestrator pipeline. The root cause of `test-ticket-fbf8` failing was `effort: "max"` being unsupported for Claude.ai subscribers — the orchestrator now clamps it to `"high"`. Along the way, fixed missing error handling in `sdkDispatch`, removed deprecated `--status` flag usage from tk integration, fixed multiple dashboard UI bugs (stage transition labels, idle run display, ticket progress bar staleness, history view status indicators), and disabled the broken KanbanBoard view.

### Decisions
- **Clamp `effort: "max"` → `"high"` in orchestrator** rather than changing all 8 agent definitions — runtime constraint handled at dispatch layer (auto)
- **Disable Board view tab** in ProjectView rather than rewriting KanbanBoard to use pipeline stages — full rewrite deferred to separate ticket `rewrite-kanbanboard-tableview-f3a7` (human)
- **Keep `status` field on Ticket type as deprecated optional** rather than removing it — too many client components depend on it; removal deferred to KanbanBoard rewrite ticket (auto)
- **Fix `getClosedTickets` to use `stage: "done"` filter** via MCP instead of deprecated `status: "closed"` — alternative was CLI `tk closed` which caused test timeouts (auto)
- **Add `refetchInterval: 5000` to ticket preview query** rather than event-based invalidation — simpler and handles all cases (auto)
- **Map "idle" runs with successful dispatches to "completed"** on disk reload rather than always mapping to "failed" — idle is a valid terminal state for manual-mode runs (auto)
- **Derive `effectiveTarget` from advancing events** for stage transition labels rather than showing raw `targetStage` ("done") — shows actual stage reached (auto)
- **Created P2 bug for verdict label semantics** rather than fixing inline — overloaded "approved" terminology for generators vs gates is a design question (human)

### Problems
- **`effort: "max"` not supported for Claude.ai subscribers** — all 8 agent definitions used this unsupported level, causing SDK child process to exit with code 1. Fixed by clamping to "high" in orchestrator. (resolved) (buggy_code)
- **`sdkDispatch` had try/finally with no catch** — SDK exceptions propagated uncaught, skipping worktree cleanup. Fixed by adding catch block and defense-in-depth cleanup in outer `.catch()` handlers. (resolved) (buggy_code)
- **Deprecated `--status` flag in tk-mcp.ts and tk.ts** — `resetTicket` passed `--status open` which caused tk to error since the flag was removed. Fixed by removing all `--status` references. (resolved) (buggy_code)
- **Triage auto-advance didn't emit `advancing` event** — UI couldn't track triage as completed stage. Fixed by adding emit call. (resolved) (buggy_code)
- **Stage transition label showed "spec → done" instead of "spec → design"** — `targetStage` was always "done" for Advance button. Fixed by deriving `effectiveTarget` from advancing events and `resolvedStage`. (resolved) (buggy_code)
- **Ticket progress bar showed stale data** — no `refetchInterval` on ticket preview query. Fixed with 5s polling. (resolved) (buggy_code)
- **Idle runs displayed as "Failed" in history** — `loadRun` and `getRunIndexEntries` mapped "idle" to "failed". Fixed to map to "completed" when dispatches succeeded. (resolved) (buggy_code)
- **"? idle" status badge in RunHistory** — missing "idle" entry in RunHistory's `statusIndicator` and `eventTypeStyle` maps. Fixed by adding entries. (resolved) (buggy_code)
- **KanbanBoard and TableView built entirely around deprecated status model** — pervasive `start()`, `close()`, `reopen()` calls to removed endpoints. Board view disabled; deferred to separate ticket. (unresolved) (wrong_approach)
- **Red herring: thought server needed restart** — initially blamed stale server for the CLAUDECODE env var issue, but watch mode was auto-reloading. The real cause was the effort level. (resolved) (wrong_approach)
- **No stderr capture on SDK dispatch** — child process errors were invisible. Added stderr callback for diagnostics. (resolved) (buggy_code)
- **11 test failures (8 newly exposed)** — removing `--status closed` from test setup let tests run that hit pre-existing Projects API timeout. Not regressions. (unresolved) (env_constraint)

### Discoveries
- Claude CLI (`cli.js` line 12438) checks `process.env.CLAUDECODE==="1"` and exits with code 1 to prevent nested sessions — unless `--team-name` is passed or it's a subcommand
- Claude CLI has a debugger detection check (`akz()`) that silently exits with code 1 if inspector/debug flags are detected
- Claude Agent SDK supports a `stderr` callback option on `query()` for capturing child process stderr output
- `effort: "max"` is only available for API users, not Claude.ai subscribers — "high" is the maximum for subscribers
- The `tk` MCP server has fully removed the `--status` flag — passing it causes tk to error
- The 13 pre-existing test failures (now 11) were partially masked by a `--status closed` setup crash that prevented downstream tests from running
- `run-store.ts` persists runs as frontmatter+JSON markdown files and maps active statuses to terminal states on reload
- Orchestrator's Advance button always sends `targetStage: "done"` with `auto: false` — the single-stage behavior is enforced by the orchestrator, not the target
